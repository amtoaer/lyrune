## 实施与验证

### 阶段 1：账户字段移动检查点

七个账户字段归入 `account::Account`，其余调用位置和顺序不变。将新字段路径逆向展开后，全部 15 个 `app/` 子模块的原有实现与 `1ac5dec` 一致（忽略格式）；`app.rs` 单独核对了七个初始值和渲染/弹层读取点。新对象没有任务或析构副作用。

复用了已有 32 项应用回归测试，全部通过；应用全部目标编译、格式和差异检查通过。纯字段移动不单独新增测试，记录为 `6e53150`。

### 阶段 1：账户规则与任务边界

`Account` 管理登录发起条件、版本失效、当前会话匹配、快照身份和凭据撤销。登录按钮/过期事件调用同一发起规则；凭据刷新与缓存验证共享同一会话匹配规则。未创建通用状态机或重复的登录事件/副作用枚举：二维码成功、过期和失败各自的 UI 编排本身很短且不同，保留直接 `match`。

等价核对：恢复、登录事件分派、凭据保存及两处账户渲染函数与 `6e53150` 完全一致（忽略格式）；账号 ID 调用在归一化所有者路径后也一致。登录发起的状态赋值仍先于通知和任务启动；退出仍依次失效所有版本、停止音频、撤销凭据、清理各领域、保存播放清空结果，最后启动原钥匙串删除任务。

会话谓词等价于“版本相同且当前凭据句柄身份相同”，不读取或修改凭据内容。缓存验证另外保留 `snapshot().is_none()` 检查；这两个本地身份条件在同一次 GPUI 更新内不会改变。刷新监听必须接收当前会话的撤销通知，因此不能把 snapshot 非空加入共用谓词。

新增两个行为测试覆盖恢复/正在登录时禁止重复发起、重试与退出后不复用请求版本、同账号替换会话、会话撤销通知仍可识别以及共享凭据的撤销。定向 2 项通过；完整应用测试 90 通过、2 个真实账号测试仍忽略；应用全部目标编译、格式与差异检查通过。未进行真实登录或钥匙串读写。

### 阶段 2：播放会话字段移动检查点

16 个播放字段归入 `playback::Playback`，包含音频设备、队列及版本、加载、当前位置和恢复信息；滑块、预览、悬停与弹层仍由视图持有。网络客户端、缓存和维护任务仍保持应用寿命。新对象未增加析构逻辑，原设备停止与任务 abort 顺序保留。

首轮编译发现歌词绘制对象也有名为 `position` 的独立字段，已修正三处误替换；这三处仍使用帧快照位置。字段路径逆向展开并统一格式后，全部 15 个子模块的原实现与 `7e72c65` 一致（导入调整除外）；入口单独核对 16 个初始值、渲染读取和 Drop。45 项应用模块测试、全部目标编译、格式与差异检查通过。此检查点只验证结构移动，未新增重复测试；下一步处理会话规则与保存快照。

- `CredentialStore` 的钥匙串格式、阻塞线程边界和异步保存/删除时序；不借结构调整改成新的串行写入协议。

# 代码结构与维护约束

本文说明当前模块职责、状态所有权、异步任务生命周期和维护时需要保留的行为约束。

## 从哪里开始读

程序入口是 [main.rs](../crates/lyrune/src/main.rs)：创建 GPUI 应用和窗口，连接托盘、单实例和 Linux 媒体控制。[app.rs](../crates/lyrune/src/app.rs) 定义 `LyruneView`，创建控件和订阅，组合主界面。

`LyruneView` 负责窗口层级、菜单状态和跨领域操作顺序，持有账号、播放、浏览和显示实体。它们在同一个 GPUI 应用线程上通过实体句柄、观察和具体事件协作。关闭窗口留在托盘时，主程序继续持有这些实体；播放、数据请求和设置保存不依赖窗口存活。

| 模块 | 负责什么 |
| --- | --- |
| [account](../crates/lyrune/src/app/account.rs) | `Account` 持有账号、凭据、二维码及登录版本；扫码登录、凭据恢复和刷新、退出及会话失效 |
| [browser](../crates/lyrune/src/app/browser.rs) | `BrowserView` 拥有普通页面、历史、页面资源索引、喜欢状态和浏览控件；接收页面请求结果与播放事件 |
| [navigation_view](../crates/lyrune/src/app/navigation_view.rs) | `NavigationView` 拥有搜索输入和导航按钮，`SidebarView` 拥有歌单列表与窗口拖动手势；通过事件交给浏览实体导航 |
| [navigation](../crates/lyrune/src/app/navigation.rs) | 页面快照、前进后退；`PageResourceCache` 管账号隔离的弱引用索引、获取和淘汰；资源类型管理结果应用 |
| [home](../crates/lyrune/src/app/home.rs)、[search](../crates/lyrune/src/app/search.rs)、[artist](../crates/lyrune/src/app/artist.rs) | 各页面的 `*PageState` 属于 `BrowserView`，各模块中的浏览视图方法负责加载、分页和显示 |
| [playlists](../crates/lyrune/src/app/playlists.rs) | `PlaylistPageState` 持有当前歌单与滚动恢复；用户歌单、分页浏览、喜欢状态及页面同步 |
| [queue](../crates/lyrune/src/app/queue.rs) | `PlaybackQueue` 的数据规则；`BrowserView` 将页面选择转换为队列，`Playback` 负责队列补全、恢复和续播 |
| [playback](../crates/lyrune/src/app/playback.rs) | `Playback` 实体拥有 `PlaybackState`、音源任务及缓存/CDN 维护；状态包含设备、队列、位置和加载版本，实体处理音源选择、音质回退和播放操作 |
| [playback_sync](../crates/lyrune/src/app/playback_sync.rs) | `Playback` 的后台 tick、曲终处理、定期保存、MPRIS 和休眠抑制 |
| [player_view](../crates/lyrune/src/app/player_view.rs) | `PlayerControlsView` 拥有歌曲信息、按钮和音量滑块；根视图组合播放栏并维持音质菜单顺序 |
| [progress_view](../crates/lyrune/src/app/progress_view.rs) | 独立进度实体拥有滑块、拖动预览和悬停状态，松手后发出 seek 事件 |
| [lyrics_loading](../crates/lyrune/src/app/lyrics_loading.rs) | `LyricsCache` 实体拥有共享歌词数据和加载接收任务；编排磁盘读取、网络刷新与结果应用 |
| [lyrics](../crates/lyrune/src/app/lyrics.rs) | LRC/QRC 解析、翻译和注音对齐 |
| [lyrics_view](../crates/lyrune/src/app/lyrics_view.rs) | `LyricsView` 拥有排版缓存、逐字高亮、滚动、封面过渡、窗口手势和显示帧调度 |
| [app/settings](../crates/lyrune/src/app/settings.rs) | `SettingsPage` 拥有输入草稿、滚动位置和输入订阅；发出 `SettingsAction`，由根视图协调缓存、字体和窗口等即时效果 |

[preferences](../crates/lyrune/src/app/preferences.rs) 的 `Preferences` 实体持有已提交的 `AppSettings`、字体、主题和唯一的设置写入队列。窗口大小、播放快照等仅供保存的数据变化不会通知所有偏好读取者。

数字设置的手动输入在回车或失焦时提交，左右步进按钮则立即提交。步进通过 `NumberInputEvent::Step` 由设置页处理，避免将输入框的普通 `Change` 草稿事件误当作保存请求。

底层模块中，`player.rs` 管音频设备与解码，`cache.rs` 管音频缓存与流，`http.rs` 管图片缓存，`settings.rs` 管设置和持久化数据格式，`credentials.rs` 管系统钥匙串，`library.rs` 管列表/表格 Delegate。

### GPUI 依赖

`gpui-base` / `gpui-component` 固定为官方 0.7.3，底层使用 `gpui-pre 0.3.9`。根 `Cargo.toml` 将相关 GPUI 包统一指向 `amtoaer/zed@b53d2343`，避免应用与组件各自使用不同来源的实体、窗口和绘制类型。

该依赖分支从官方快照 `93d74566` 迁移 Lyrune 的局部重绘、动态非活动帧率、字形变换和可变字体补丁，再通过组件仓库的官方导出脚本生成独立工作区；原 Wayland 帧循环补丁已被上游包含。补丁及生成方式记录在依赖仓库的 [LYRUNE-GPUI.md](https://github.com/amtoaer/zed/blob/b53d2343e5b238ca090fa321187180d3e37f7d7c/LYRUNE-GPUI.md)。升级时需一并检查这些补丁，不能仅替换组件版本。

### 工作区与协议库

工作区现由三个内部 crate 组成：`crates/lyrune` 是桌面应用，`crates/lyrune-api` 是 QQ 音乐协议实现，`crates/lyrune-decrypt` 负责 QMC 音频解密。包名与目录名一致。

`lyrune-api` 仅供 Lyrune 内部使用，根入口选择性导出应用需要的能力，各领域模块直接实现 `ProtocolClient` 的方法。登录、播放和 CDN 使用的标识各有协议含义，不能因外形相似而合并；`QqCredential` 和 `LyricResult` 是持久化兼容面。协议库入口与来源说明见 [API README](../crates/lyrune-api/README.md)。

### API 响应与领域边界

| 模块 | 当前职责与保持的约束 |
| --- | --- |
| `account.rs`、`login.rs` / `login/` | 前者拥有凭据快照、刷新锁、撤销和扫码编排；后者实现登录 HTTP 与 MQTT。扫码完成后调用客户端补全 encrypted_uin，普通查询依赖会话刷新。 |
| `client.rs`、`signing.rs` | 通用签名网关先检查全局码和业务码，再移出 data。登录和业务请求共享签名运算，各自保留 Cookie、GUID、代理、超时和响应错误策略。 |
| `client/library.rs` | 资料、歌单、推荐、喜欢状态及共享歌曲转换；歌单分页过滤无 mid 条目，并按服务端原始条目数推进游标。资料旧接口是否请求由字段存在性判断决定。 |
| `client/search.rs` | 首批四类别并发、各类补页和歌手专辑；移动端歌曲 type 转换与两种分页规则分别保留。 |
| `client/playback.rs`、`client/cdn.rs` | 前者解析普通/加密音源，后者拥有 CDN 调度和节点/地址规则。两类音源采用私有 PlaybackEntry，保留 purl 键存在时禁止 wifiurl 回退、质量去重与 ekey 检查顺序。 |
| `client/lyrics.rs`、`lyrics/qrc_des.rs` | 私有 LyricResponse、歌词回退与解码、QRC 算法。 |
| `client/response.rs`、`models.rs` | 前者仅保留字段兼容与递归查找，后者持有应用共享数据与序列化格式。网络结构体只存在于使用它们的领域。 |

歌曲的多种包装/别名、搜索与推荐不同的无效条目规则、资料的未知嵌套和 CDN 的双列表合并使用局部 Value；普通 alias/default 无法完整表达现有优先级、非法类型及层级规则。没有充分证据时不删除这些兼容分支。进一步类型化须证明比现有直接流程更清楚，并保持接受范围。

## 关键调用关系

1. `LyruneView::new` 创建控件、接入事件，然后恢复账号。账号可用后加载首页和音乐库；音乐库加载还会触发已保存队列的恢复。
2. 导航先建立目标页及其资源，再记录当前页、应用目标页。搜索、歌手页面的请求完成后，由 `SearchResource` / `ArtistResource` 应用结果并结束相应加载状态；回调在释放资源锁后，按资源身份决定是否更新当前控件。资源方法不操作 GPUI，也不判断当前页面。
3. 歌单页和歌手页选曲共用 `select_playlist_track`，统一判断复用队列、切换暂停或建立新队列；搜索结果仍按独立规则插入当前歌曲之后。随后调用 `start_playback`，Tokio 任务通过 `prepare_playback_stream` 复用或重新解析音源，再到阻塞线程准备解码器；GPUI 回调检查播放版本后才调用 `AudioPlayer::replace`。
4. 后台 tick 读取音频进度、判断曲终、保存播放状态并同步系统媒体控制。歌词显示与进度条分别按各自设置运行窗口帧回调，共享实际音频时钟。

`LyruneView::playback` 是播放实体句柄，音频设备以 `Arc` 供歌词和进度视图读取同一时钟；滑块和悬停预览由 `PlaybackProgressView` 持有，音质菜单的开闭由根视图协调。会话内的 `PlaybackLoad` 统一维护请求版本、版本检查和加载标记清理。`invalidate` 只使旧结果失效，`clear` 只清除加载索引与播放意图，保留版本；退出账号时不能用默认值替换整个会话或加载对象。调用处保留以下顺序：

| 触发 | 加载状态与外部操作的顺序 |
| --- | --- |
| 开始播放、切歌或切音质 | 停止设备、请求歌词 → 递增版本 → 设置索引、播放意图和位置 → 发出 TrackStarted、保存快照并启动音源任务；浏览实体收到事件后检查喜欢状态 |
| 加载完成 | 检查版本 → 清除加载标记 → 装入音源，或按原错误路径提示并跳歌 |
| 停止播放 | 递增版本 → 停止设备 → 清除加载标记 |
| 退出账号 | 递增版本 → 停止设备 → 撤销凭据、清理页面和队列 → 清除加载标记 |

## 容易误改的约束

### 账户任务的边界

`Account` 拥有账户状态、凭据句柄、资料、二维码、登录版本和文案。它拥有凭据恢复、扫码、会话监听、验证和保存任务，登录状态与凭据安装在同一次账号实体更新中完成。`AccountEvent` 将登录成功、会话失效和错误交给根视图；根视图协调浏览加载、退出清理和窗口通知，收到失效事件时再次核对版本及会话身份。

| 任务 | 启动与结果处理 | 失效/结束规则 |
| --- | --- | --- |
| 恢复凭据 | 构造后一次启动，Tokio 阻塞线程读取；成功后安装会话并加载首页和音乐库，无凭据/失败时进入二维码登录 | GPUI 实体销毁后无法应用；该任务没有独立请求版本或取消策略 |
| 二维码登录 | `Account::begin_login` 阻止恢复中或登录中重复发起；事件更新二维码/文案，成功安装会话，过期自动重试，失败等待点击 | 结果应用前比较登录版本；成功/过期/失败后结束当前事件接收循环；Tokio 任务不因丢弃句柄而取消 |
| 凭据刷新监听 | 安装会话时先订阅，再保存当前快照；刷新后保存新快照，撤销后清理账户并提示 | 登录版本与句柄身份同时匹配；同账号的新会话也会使旧监听失效；当前会话 snapshot 为空时仍必须接收撤销通知 |
| 缓存凭据验证 | 使用缓存音乐库时进行 30 秒限时验证，仅失败时提示 | 版本和会话身份匹配且 snapshot 仍有效时才提示 |
| 保存/删除凭据 | 保存捕获快照，删除在退出清理末尾启动；均通过阻塞线程执行 | 独立后台任务，失败时通知；没有写入排序或版本过滤 |

### 控件、设置与长任务

`SettingsPage` 内的 `SettingsInputs` 拥有设置输入框及默认值、掩码和校验，`set_fonts` 仅回填三个字体输入框。“恢复默认”先改输入框，“应用字体”才更新字体、主题、排版缓存并提交保存。其他设置的读值、即时生效、保存和通知顺序由各自的事件处理方法负责。

`Preferences` 持有唯一的 `SettingsWriter`，UI 将 `AppSettings` 快照发送到 FIFO 队列，不防抖或合并；文件更新会晚于 UI 提交请求。保存任务逐条等待 `spawn_blocking` 完成；`SettingsStore` 消费快照，规范化、序列化后写入同目录临时文件，再用 rename 原子替换正式文件。保存途中进程终止不会截断已提交的配置；残留临时文件不参与启动读取，下次保存时覆盖。磁盘回写交给操作系统，不使用 fsync，不承诺断电后的持久性。保存错误当前被忽略。

`LyruneView::new` 创建领域状态、控件和订阅，随后 attach window、报告初始化错误、启动音频缓存/CDN 维护、恢复凭据、按设置安排更新检查。保留订阅句柄使回调持续有效；根视图、浏览视图和设置页在 `attach_window` 替换窗口绑定的订阅，歌词和进度视图递增窗口版本并恢复帧调度，旧回调不能接管新窗口。浏览补页及表格事件接收器通过 `cx.spawn` 跟随浏览实体；需要窗口的操作每次取最新句柄，窗口关闭时忽略残留 UI 事件，但不结束接收循环。

CDN 维护和音频缓存维护由 `Playback` 保存 JoinHandle，重启维护或关闭应用时显式 abort。CDN 成功刷新后通过阻塞线程保存，刷新失败后等待 60 秒再进入下一轮。更新检查延时启动并重新读取开关/进行中状态；完成后按“手动/自动”区别通知。通知经当前记录的窗口句柄 defer，交给根视图持有的 `NotificationList`；窗口重开时创建新列表，旧窗口的通知不会转移过去。

退出回调调用 `shutdown`：先提交播放快照、停止音频，再提交其余偏好，关闭发送端并等待保存队列排空，最后 abort 两项维护。第一步可能因无账号/当前曲或快照没变化而不保存，所以不能删除第二次保存。等待放在退出回调返回之前：GPUI 对退出 future 的等待仅有 200ms，macOS 终止也不保证返回 main。工作线程不访问 GPUI，不依赖 UI 继续轮询。GPUI 的实体释放回调复用同一清理入口；已取走的写入者和设备不会再次保存或停止。关闭窗口留在托盘时不会结束写入者。

### 浏览状态和请求边界

搜索、歌手、首页和歌单各自的 `*PageState` 保存当前页选择、可见数量或加载状态。它们没有自己的任务句柄；`BrowserView` 在各页面模块编排任务。`NavigationPage` 是历史快照，保存资源强引用而不复制请求结果；控件由浏览实体持有。页面切换按字段清理，不用整个页面 Default 代替，以免丢失历史选择或重用版本。

搜索/歌手请求先更新共享资源，再比较当前页资源的 Arc 身份；离开页面不取消请求。歌单页面与播放补全通过既有 SingleFlight 共享请求，资源的 offset 规则拒绝重复回填。库目录和首页请求分别比较自己的版本；喜欢操作继续比较账号 ID。缓存保存策略、错误状态和这些过滤条件均不统一成通用框架。

### 歌词任务的边界

`LyricsCache` 管磁盘句柄、已采用内容、待采用内容、正在加载和错误状态。`ensure_track_lyrics` 按 TTL 与加载集合去重；后台任务经容量 2 的通道依次发送磁盘和网络事件，接收任务更新 `LyricsCache` 并通知。是否仍为当前曲通过 `WeakEntity<Playback>` 读取真实播放状态，不另外维护一份当前歌曲标记。缓存按歌曲 mid 共享，不随退出账号或离开页面清空，没有会话版本过滤。

旧磁盘内容可先显示，失败不覆盖已有内容；正在播放且已有内容时，不同的网络内容暂存，相同内容只更新时间并保留原 Arc。`adopt_pending` 在开始请求前、该曲尚不是当前曲时调用；切同一歌曲或切音质不强制替换时间轴。原始磁盘保存仍先于 Network 事件，排版和帧面板仍由 `lyrics_view` 管理。

### 播放任务的边界

`PlaybackState::replace_queue` 使旧队列补页和推荐周期失效，不改变音源版本；随后播放入口停止设备并开始音源请求。搜索插队沿用原队列版本，允许正在进行的补页追加。`PlaybackState::snapshot` 负责恢复数据的内容，`Playback` 负责保存触发点并提交快照到 `Preferences` 的写入队列。加载中或尚未开始时使用显式恢复位置，设备时钟可能还对应上一音源。

| 任务 | 结果与结束规则 |
| --- | --- |
| 音源准备 | Tokio 解析/复用音源，阻塞线程准备解码器；GPUI 接收事件先检查音源版本，再替换设备。失效仅拒绝结果，不取消后台准备。 |
| 歌单补全 | Tokio 请求可先更新持有的页面资源；GPUI 检查队列版本后才追加当前队列。 |
| 推荐补充 | 首批推荐检查独立请求版本与当前加载类别；队列续播检查队列版本，预取标记与队尾等待标记分别决定加载和接续播放。 |
| 进度帧回调 | `PlaybackProgressView` 使用窗口帧回调和自己的帧率截止时间；暂停、拖动或设备不再推进时停止周期采样。窗口重开递增版本，排除旧回调。 |
| 后台 tick | `spawn` 跟随应用实体；窗口关闭后仍判断曲终和保存，暂停时通过通道唤醒。 |

MPRIS 在音源加载期间沿用 `Playing` 状态；它与 `PlaybackState::is_advancing` 描述的设备实际推进不同，不能合并成一个播放布尔值。

### 窗口组合与刷新边界

普通页面、歌词覆盖层、底部 112px 播放栏在窗口中分别组合。根视图只计算一条歌词展开进度，同时驱动覆盖层裁剪和 CSD 按钮颜色。只有已展开的区域遮挡鼠标；完全展开后不挂载普通页面，浏览实体、历史和进行中的请求仍然保留。播放栏的专辑/歌手导航先收起歌词，再调用浏览实体。

浏览实体拥有导航、侧栏及页面，但它们在渲染树中是兄弟：页体使用 GPUI `cached`，搜索输入和可调整面板位于该缓存外；导航、侧栏和设置页分别缓存。搜索输入变化使导航缓存失效，不重建页体。根视图的动画帧不会主动通知浏览实体。主题、页面资源、导航和尺寸等实际变化仍使相关视图失效。gpui-component 0.7.3 已修复输入框无变化时重复通知的问题；缓存回归测试也覆盖设置页滚动到输入区域的情况。

图片 LRU 与视图的 element state 共同持有图片条目。`cached` 重放会保留 element state，但不会重新访问图片 LRU，因此淘汰条目时不能立即释放 GPU 图片区域；只有 LRU 和视图都不再引用它时才释放。容量设置限制 LRU 条目数，当前渲染树使用中的图片可以额外保留，页面移除后随 element state 释放。

播放信息/按钮与进度条同样使用兄弟缓存边界，不能把周期更新的进度条包进播放控制区的缓存。进度帧只更新进度实体；歌词实体自行维护高亮和滚动帧截止时间、排版缓存与本帧面板。后台 250ms tick 和约 5 秒保存检查不依赖这些显示帧。

歌词高亮与滚动分别更新面板中的时间和位置采样；其中一个到期不能带动另一个提前刷新。限帧的滚动仍需采样最终目标位置，暂停时的跳转和字号、间距变化则直接使相关面板缓存失效。

歌词完全收起时使用视图缓存，避免零高度裁剪下仍随进度帧重建布局。实体和资源预热保留，切歌、内容或设置变化仍会使缓存失效；歌词可见及展开、收起过渡期间不使用该视图缓存。

新版组件的 Root 不再暴露通知实体，Lyrune 因而自己持有列表并显式组合其位置。通知保持在根组合中的原位置；菜单关闭遮罩使用 deferred 优先级 5，账号菜单为 10，音质菜单和 CSD 控件为 20，继续保留原来的绘制与点击次序。不要用一个统一的“最高覆盖层”改变它们。

### 跨领域不变量

- **浏览状态与播放状态独立。** `playback.current_track`、`playback.load.track` 是播放队列索引；页面选中行不能直接当作队列索引。插入搜索歌曲会标记 `queue.modified`，此后不能仅凭原歌单 ID 复用队列。
- **队列追加保留已有歌曲。** `PlaybackQueue::append_tracks` 按 `mid` 去重，保留已有歌曲的位置和元数据；只返回第一首新增歌曲的索引，重复批次返回 `None`。页面播放标记通过 `playback_indices_in` 按歌曲身份映射，页面重新排序或缺少歌曲不会误用队列索引。
- **播放字段描述不同阶段。** `playback.load.autoplay` 在加载期间保存播放意图，连续切换音质时不能从已停止的设备推断。`playback.started` 在暂停时保持为真；`playback.active_quality` 是实际音质，可能低于持久化的用户偏好。`ResolvingOptions` 事件通过有界通道发送，接收时同步列表并通知界面。
- **推荐预取与等待续播独立。** `playback.recommendation_loading` 可以在当前歌曲仍播放时为真；只有 `playback.waiting_for_recommendation` 才要求结果到达后从新增歌曲开始播放。
- **历史记录拥有页面资源。** 当前页、历史记录和进行中的请求持有 `Arc`，`PageResourceCache` 只保存 `Weak`。清空前进历史之前先取得目标资源，否则可能失去可复用的最后一个强引用。缓存键包含账号，结果是否属于当前页用 `Arc::ptr_eq` 判断。
- **补页失败保留已有结果。** 搜索的各类别可以同时补页，某类别成功不能清除其他类别的错误；歌手的歌曲、专辑各自结束加载并保留各自的错误。首次搜索成功会清除原搜索错误，歌手请求则在启动前清除对应错误，这些时机不同。请求前的检查还涉及历史页面的可见数量和通知，继续留在页面方法内。
- **分页可被两个用途共享。** 页面补页和播放队列补全通过 `SingleFlight` 共享同一账号、歌单、offset 的请求。资源只追加期望的下一页，避免重复回填。队列切换后，旧任务仍可能补全自己持有的页面资源，但不能覆盖新队列。
- **失效与取消是两件事。** 登录、音乐库、首页、队列和音源加载分别使用版本计数器。它们拒绝晚到的结果，并不会自动终止网络请求。凭据刷新还比较会话身份，防止同一账号的旧会话影响新会话。
- **显示帧与后台 tick 的寿命不同。** 进度控件按 `progress_frame_rate` 采样音频位置（旧配置默认 60 FPS），与当前页面、歌词是否展开无关；其他视图重绘不能绕过该帧率。窗口关闭后应用 tick 仍处理曲终与保存，暂停时等待通道唤醒。窗口重开通过 `attach_window` 重建显示帧链。
- **歌词有多层缓存。** 原始磁盘缓存、已解析内容、排版结果和当前帧面板各自解决不同问题。已有歌词正在播放时，网络刷新得到的不同内容先进入 `lyrics.pending`，以后选中该曲时采用，避免本次播放中时间轴突然变化。
- **歌词时间和排版不能按字符数简化。** 字范围是 UTF-8 字节下标；没有字级计时的标点和尾部文字借用相邻时间段。QRC 的严格与宽松解析都覆盖真实格式差异，现有测试包含未转义属性和截断输入。
- **自绘和帧率缓存有用途。** 歌词缩放复用已排版字形；进度条用路径避免设备像素取整造成跳动。面板缓存让其他控件重绘时仍遵守歌词帧率限制。`expanded`、`visible`、`fully_expanded` 分别表示用户目标、过渡可见性和跳过底层页面渲染的时机。

网络与阻塞准备任务使用 [runtime.rs](../crates/lyrune/src/runtime.rs) 的共享 Tokio runtime；GPUI 实体通过 `cx.spawn` / `this.update` 接收结果。`drop(RUNTIME.spawn(...))` 让 Tokio 任务继续运行，不能理解为取消。长期维护任务保存 `JoinHandle`，重启维护或实体销毁时显式 `abort`。

## 已知限制与后续事项

| 位置 | 当前证据与下一步需要的证据 |
| --- | --- |
| 歌词收起时的首帧 | Linux release 隔离窗口中，稳定动画帧较轻，但每次从完整歌词页收起的首帧仍出现约 33～55ms 的 CPU 绘制耗时，主要在 prepaint。普通页面此时重新进入渲染树；还需调用栈采样确定具体成本，不能据此声称已消除所有卡顿。 |
| `lyrics_loading::ensure_track_lyrics` 的异常收尾 | 磁盘旧内容已采用后，若后台任务异常结束而未发送 Network，收尾可能留下该歌曲的 loading 标记。该标记仅在内存中，重启后清除；需要受控异常复现，再决定恢复行为。 |
| `SearchCardGridDelegate::set_cards` 的参数列表 | Clippy 报告参数过多。参数分别描述数据、布局和分页状态，目前只有一个调用点；后续若布局需要独立复用，再评估其边界。 |
| `AudioCache::prepare_for_seek` | 仅在测试中使用，覆盖跳转 Range 请求且不发送 HEAD 的路径；删除前需要替代这项覆盖，并重新判断 `validate_remote` 的用途。 |

## 验证

按改动涉及的包和行为选择检查范围，常用命令如下：

```sh
cargo check --locked -p lyrune --all-targets
cargo test --locked -p lyrune
cargo test --locked -p lyrune-api
cargo clippy --locked -p lyrune --all-targets
cargo fmt --all -- --check
git diff --check
```

应用回归测试在 [app/tests.rs](../crates/lyrune/src/app/tests.rs)，显示边界测试与各视图同模块，纯解析测试在 `app/lyrics.rs`，协议测试与实现同模块。现有测试覆盖页面资源寿命、分页结果、历史滚动位置、队列去重、请求版本、歌词计时和缓存等关键约束。部分缓存测试启动本机 HTTP 服务，需要允许绑定回环端口；真实账号测试默认忽略，需要系统钥匙串中的凭据和 QQ 音乐网络访问。

实际 GPUI 测试另覆盖：30 次覆盖层更新不重建稳定浏览页和导航，缓存后的搜索框仍可点击输入；进度更新不重建播放控制区；隐藏页面保留历史；关窗重开后搜索仍响应；设置草稿不提前提交，重绑窗口不重复处理输入；进度滑块松手才发出 seek。它们证明状态与缓存边界，不代表真实显示器上的帧率测量。

以下是人工回归检查项，不代表已经完成验收；自动测试不能替代真实账号、网络、钥匙串、音频设备和桌面交互验证：

- 扫码登录、二维码过期重试、退出、重启恢复凭据，加载期间切换账号或页面。
- 搜索和歌单前进后退、恢复滚动位置、加载中离开页面后返回，同时保持原队列播放；分页失败保留已有结果。
- 快速切歌、加载中切音质、音质回退、拖动进度、暂停续播和推荐队尾续播；旧请求不覆盖当前歌曲。
- 歌词展开/收起、字体与帧率切换、切歌时封面和歌词过渡。
- 设置即时生效、字体输入应用、退出后重启确认偏好和播放队列恢复。
- 有托盘时关闭并重开窗口，媒体键/MPRIS 控制和退出后的队列恢复。
